# Career snapshot paging

Career profile compilation is a paged protocol: exact, lossless source segments are deterministically packed in source order into pages of at most 32 segments or 48,000 source characters. A page never truncates a segment; an oversized segment stays whole and the normal per-call prompt guard fails explicitly if it cannot fit.

Compile and repair responses use the capped page schema. The host gives new entities a stable `pNNNN-` namespace and retains an explicit bounded active role/project state across any number of intervening pages (`inherit`, `replace`, or `clear`). A later page can therefore attach a responsibility or skill to an earlier role without re-emitting it. Literal fields split at a page boundary use page-local `rolePatches` or `projectPatches`; the host accepts only an empty-field completion or an exact repeat, unions the patch evidence, and rejects conflicts. Source-file metadata in a page call is limited to files represented by that page.

The host reconciles only semantically compatible cross-page duplicates. Compatible role/project records retain a lossless reconciliation receipt; skill reconciliation additionally requires the same canonical name, category, and `indexEligible` value. Narrow host-side cross-page candidate comparisons surface incompatible distant role/project duplicates to their owning pages instead of choosing one. Reciprocal role links are restored before final literal-grounding validation.

All six audit disciplines run for every page through the shared bounded worker pool. Descriptors are claimed lazily and each page/category receipt stores a chained digest and count; a tiny diagnostic sample is retained only at the category level, never multiplied by page count. The full finding array exists only while its page is being repaired. Older detailed rounds fold into a chained compact receipt, so retention never becomes a total-repair-round limit. The first audit pass is receipt-only, so a repeated global state is rejected before another repair; affected pages are then re-audited in bounded batches for repair detail. A finding repairs only affected pages; deterministic failures use paged complete replacements. The full audit set then reruns. Approval requires a clean full host validation, current convergence digests, a page receipt for every category/page pair, and a reconciliation receipt; historical v2/v3 pins use their explicit compatibility validator. A canonical-identical repair or repeated unresolved state is nonconvergent.

The old roles/achievements/projects/skills/other-evidence response maxima are per-page output safety limits, not profile limits. The host merged-profile schema has no array response caps. Current v5 also has no total segment-count or frozen-application-projection approval cap: source lines and structured authority page until the immutable 64 MiB snapshot/file envelope or a per-call schema/token/prompt bound is reached. The 5,000-segment ceiling remains only for explicit v2/v3/v4 historical-pin validation. The separate 240k raw frozen-source limit applies only to legacy unpinned application handling.

## Attachment and scoring pages

Attachment transcription policy revision 8 inventories non-plain containers in bounded batches. Each AI-container inventory batch is independently rechecked and added to a compact chained audit receipt; the 100-region schema maximum is a single-call bound, never a document limit. The host assigns a stable `expectedPageId` from `(regionId, partIndex)`. A worker must echo that id, the region identity, and the zero-based part index; a part can continue only within the same region, and every region must complete before the final page can complete. Adjacent-part boundary checks carry both region and part metadata.

Current attachment receipts are v3 and use the shared canonical JSON digest for inventory, page, boundary, and coverage arrays, so their hashes remain valid after a canonical snapshot write/read. Current validation requires exact keys, exact aggregate sums, contiguous region-part coverage, and current policy digest. Older v2 and pre-canonical v3 receipts are accepted only when reading an explicit historical pin.

Pinned scoring sends one bounded approved-evidence page per call. The host retains a pageable requirement/status/evidence ledger for every response and reconciles full normalized requirement text, priority, and posting evidence—not prefix-clipped display fields. No final model sees a top-N reduced summary: the host deterministically composes the result from all page rows. Thus the 24k evidence-page ceiling is per handoff/ledger page and cannot reject or erase a larger aggregate career ledger.
