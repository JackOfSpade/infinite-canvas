## Stages

**Test ownership (round 4; closes the unordered-writer and circular-acceptance gaps the second verification found).** Nearly every Acceptance line below describes tests, but a registered test file (all created and registered once, by B0.5) has ONE writer at a time, and a task whose Files omit the test file its acceptance names is one of two things. (a) An ordered writer: it writes into the registered file its acceptance names, and every other writer of that file is its ancestor or descendant in the dependency graph, so no two unordered tasks edit one file. The writers, in order: `handoff-bridge-inert.js` B0.3 (I-01 to I-06, I-15, I-16), then B6.5 (I-07 to I-14, I-17); `-http.js` B1.1 (its wire and respond cases), then B1.4; `-mcp.js` B1.2, then B1.3; `-oauth.js` B2.3, then B2.4 (B2.1 and B2.2 write no test file: their acceptance is proved by B2.3's ported steps and new tests); `-engine.js` B4.1, B4.2, then B4.4; `-application.js` B4.3; `-store.js` B4.5; `non-api-ai-bridge-seam.js` B5a.2; `-hostile.js` B8.6; `-ui.js` B7.1, then B7.2 (B7.3 and B7.4 commit no test). `-privacy.js` and `-source-scan.js` are written by B6.5 and then B8.2 (B8.2 depends on B6.5); the whole scan table itself is B0.5's. (b) A specification: the Acceptance lines of B3.1 to B3.4, B6.1 to B6.4, B5b.1 and B8.4 describe tests that ONE later task writes: B3.5 writes every registered test of stage B3 (`-tunnel.js`), B6.5 writes `-controls.js`, `-ipc.js`, the stage-B6 parts of `-privacy.js` and `-source-scan.js`, and I-07 to I-14 and I-17, B5b.2 writes `-push.js` (including the two throw-injection cases B5b.1 names), and B8.2 writes the redaction tests B8.4 specifies; in stage B0 the acceptance lines of B0.2, B0.4 and B0.6 (constants, contracts, validators, harness self-tests, goldens) are likewise specifications of the skeleton tests that B0.5 writes into the files it creates, and B0.3 writes the inert file itself. The earlier task of a specification checks itself with uncommitted scratch runs and its G0 allow-list is its listed Files only. This also removes the circularity of an acceptance that depends on a test a later task writes: a specification is met when the named later task's test passes at that stage's gate.

## Residual risks Jack accepts

- Cloudflare and OpenAI read every prompt and answer in plaintext; every served application prompt carries the career corpus, so per-job release limits which listings and drafts are exposed, not the corpus. Cloudflare terminates TLS and sees the bearer, the chat code, prompts and answers, and cloudflared's management service can stream connector logs to whoever holds the Cloudflare account (whether debug-level headers can be pulled is X6): the account is part of the credential trust root, no origin-side control fixes that, and only account hardening (Jack's item 15), source enforcement and `private_key_jwt` narrow replay.
- The OAuth link is not account-bound: ChatGPT's client document has one redirect for every user, so a stranger's plugin looks identical to yours. Only the pairing code, the same-network TRIPWIRE (a shared public IP passes) and the 10-minute window stand between a stranger and a link; screen sharing or shoulder surfing during pairing defeats them, and pairing-window fatigue is a real social-engineering surface once Reconnect is routine (the 3-day idle and 14-day absolute lifetimes make it routine).
- Client authentication (round 2): until gate MG1 shows ChatGPT signs `private_key_jwt`, a refresh token is a bearer credential (ChatGPT's real document declares `private_key_jwt`, Phase 0 saw `none` only because the lab advertised `none`); theft inside the 120 s grace window is invisible. If ChatGPT does NOT sign when only `private_key_jwt` is advertised, production stays on `none` and that stays true, bounded only by the lifetimes, source enforcement and the release set; even with MG1 passed an access token replays for up to an hour from the link-time network or OpenAI's ranges. Reuse detection is availability-hostile by design: before MG1, anyone from those networks holding one stale refresh token can force a revocation, and recovery needs a pairing window at the Mac (drill M20; nothing is exposed meanwhile).
- Prompt injection is bounded only by model behaviour: 0 of 9 canaries allows a true failure rate up to about 28% at 95% confidence, one model and effort, browsing state never recorded; another tool in the same chat (memory, browsing, other apps) is an exfiltration path the app cannot police; the bound also covers only one injection style (echo a marker, open a URL) and says nothing about subtle steering of scoring or résumé content. Second-order integrity: even with every control, a poisoned but validator-passing answer from a steered model is written into your application files and scoring; your review of the finished output is the only mitigation, and unattended draining reduces it.
- The public hostname is fingerprintable and floodable whenever the app is open with the bridge on (a random label cuts scanner noise and hint spam, it is not a boundary). The app sheds load (separate authenticated pools, credential-less-only aggregate charging, an abuse-suite stall budget) but deliberately has no listener-closing breaker, so a flood can still deny legitimate calls if the stall budget is missed; a rogue second connector or hijacked DNS record is invisible from the origin.
- **D5 and the idle pause (round 2, decision 19; wording pair fixed in round 4):** ON (the default): a soft pause of `tools/call` after 24 h without a HUMAN epoch action that ends nothing (the tunnel, link, epoch and release set stay up, one click resumes), a deliberate departure from D5's literal no-timer wording. OFF (`idlePauseMinutes` = 0): D5 literally, with no clock on a stolen credential: a stolen link, chat code and release set stay usable until quit, Disable, Revoke or the epoch closes with the queue, and the only detectors are the two ledgers, the 12-hour serve-after-idle notice and source enforcement. The other bounds are data conditions: the release set (held after every restart until one native confirm), the memory-only 130-bit chat code bound to the link, the epoch closing when the queue drains, the 2-job cap, the byte budget, anomaly pause, Pause/Revoke and Tray visibility.
- The app-spawned cloudflared can be orphaned by a crash or Force Quit for under 5 seconds: the /bin/sh watchdog polls the app pid every second and then escalates TERM, a second TERM and KILL (measured bounds in scratch on this Mac, addendum 12.2: a polite child gone about 0.3 to 1.3 s after the crash and a child that ignores TERM up to about 4.6 s, depending on where the poll falls, so the gates assert 6 s; a plain `sleep 2` loop would defer the TERM trap by up to 2 s, which is why the loop is `sleep 1 & s=$!; wait $s`), and for longer only if the shell wrapper itself dies; cloudflared's own grace period is forced to 2 s (its default is 30 s); the next launch reaps a survivor, and that launch does one `stat` and spawns `ps` only if a stale pidfile exists. The Homebrew binary is ad-hoc signed with no Team ID, so authenticity rests on a trust-on-first-use SHA-256 pin of an app-owned COPY that detects change and cannot prove the file is genuine.
- **Same-UID attackers are out of scope but named:** any process running as you can connect to the socket (and forge `Cf-Connecting-Ip`), rewrite the pin, the tunnel config, `oauth-state.json` and `lanes.json`, swap the binary copy between the hash and the exec, and read the clipboard. **The renderer has no CSP** (index.html): native confirms are the only boundary and every exposure-raising IPC is confirmed in main; adding a CSP is a separate app change, recommended, not part of this plan. The starter (with the chat code) can sit in clipboard managers and Universal Clipboard beyond the 120 s clear.
- Hand-rolled OAuth and MCP code in the privileged Electron main process is the only parser of untrusted bytes, and the process-wide `uncaughtException` handler swallows and continues (main.js:215-222), so a logic bug degrades silently instead of crashing; mitigations are the ported 100-step suite, the import allow-lists, the negative battery, the permit watchdog and finally-release rule, the abuse-suite stall budget and a /security-review before any real data crosses it (isolation in a `utilityProcess` would fix event-loop coupling only and is unscoped).
- Renderer-driven job completion: a bridge chat can only drain to paste-completed; import, PDF fit and measured-fit reopen need an open canvas window. With no window a job stalls as host_silent after 10 minutes and macOS keeps the app alive with no window.
- Chat context is the binding limit for scoring: about 60 KB prompt plus 40 KB answer per handoff means a chat may take only about 4 handoffs before New chat, and one serial chat is roughly 3 to 4 times slower in wall clock than ten manual chats (it saves your attention, not time); with waves of 10 and repeated `get_handoff` reads counting against the 900 KB hard budget, a 20-wave run is roughly 25 to 40 starter pastes, so `scope.scoring` stays off by default until S5 reports handoffs per chat and block rate. 35 to 65 KB tool-call arguments are unmeasured (largest ever sent 25.7 KB) and a chat can end one scoring phase early because phase changes are renderer-driven.
- ChatGPT-side blocks never reach the server (one after a reconnect was seen); a new plugin has an unexplained early write-block window of about 20 minutes; whether editing tool text or the URL resets the warm-up, sleep, renderer throttling and a real 2-hour outage are unmeasured.
- get_handoff keeps readOnlyHint:true although it can write in recovery paths (localAiApplication.js:3699-3711); the Generation Log crash window (D7) remains until you schedule that separate app change; bug reports cannot tell bridge rounds from pastes without the optional D10 telemetry.
- Several small deltas from the linked lab configuration are unmeasured until acceptance: client authentication (`private_key_jwt` verified in two stages: staging advertises both methods, production advertises only what MG1 justified, and `none` is refused once stage 2 is on), the Origin and `Sec-Fetch-Site` policy (observe-only on the server-side routes until MG5/X4, then enforce), the Unix-socket origin through the real edge (X1), how cloudflared treats a client-supplied `Cf-Connecting-Ip` and `Expect: 100-continue` (X2, X3), whether pprof is reachable on the metrics port (X5), OpenAI's published connector ranges behind source enforcement (X8), the new `caution` field on rejected results, the v2s tool text and starter used for scoring prompts (provisional until S7, one deliberate revision allowed), /ready and edge status-code mappings for cloudflared, the Host header through Cloudflare, the `Cf-Connecting-Ip` family and iCloud Private Relay or a VPN against the same-network pairing gate, renderer throttling and Mac sleep mid-drain (keep-awake decision at B9/S2), and the watchdog wrapper behaviour on macOS (measured on this Mac with a fake, not with the real cloudflared).
- A stage that has merged to local main is unpushed work until Jack pushes; a Mac loss before a push loses it (open decision 15).

## Contradictions between the analysts and how they were resolved

- Release model under D5: the UI analyst had renderer-published jobs flowing continuously with no per-job confirm; the application analyst and security analyst required a main-owned native confirm per release and warned the renderer has no CSP. Decision: persisted release set with a native confirm per batch; the renderer only publishes CANDIDATES (with a change signature) and a sanitized label crosses IPC only on the release call (**superseded in round 2**: NO label crosses IPC at all, main derives every word of a native dialog from disk, E2, and the publisher sends `{jobId, canvasFilePath, dockState, sig}` only); optional autoRelease (own confirm, default off) gives the hands-off experience.
- Timers under D5: the security analyst proposed default release lapse 24 h, chat-key max age 24 h and idle pause 180 min; the application analyst and the literal decision say no timers. Decision: the controls exist but default to 0 (off), each raising change needs a native confirm, and data/count-based controls (release set, 2-job cap, byte budget, anomaly pause, Pause/Revoke, visibility) carry the load. Recommended values are documented for Jack to switch on. **Partly superseded in round 2:** release lapse and chat-key max age stay 0, but the idle pause now defaults to 1440 min measured from the last human epoch action (a soft pause, decision 19).
